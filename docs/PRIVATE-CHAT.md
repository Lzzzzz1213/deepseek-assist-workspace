# 固定 DeepSeek 私聊与本地记忆

首页“鲸鲸 · 来聊聊呀”进入唯一的私聊。没有话题列表或新建会话；返回后再次进入仍是同一段聊天。支持 Enter 发送、Shift+Enter 换行、历史分页、长文展开与本地表情。页头默认居中显示“鲸鲸”，回复中在同一位置显示“对方正在输入中…”，结束或失败恢复；清空和主动聊天开关放在竖三点菜单，不再显示记忆数量。

客户端固定称呼由 `role_identity.py` 定义并随每次私聊提供：鲸鲸／小鲸鲸／小鲸鱼／大肥鱼／DeepSeek／DeepSeek Flash 指同一角色；龙龙／ChatGPT／GPT 指主智能体。别名同时扩展记忆检索词，不改用户原话或历史正文，不用昵称匹配进程、文件、模型或权限。应用品牌仍为 `DeepSeek协助工作区`。例如“小鲸鱼，龙龙那边给你安排了什么活”会按公开工作摘要理解，不因称呼不同虚构新角色。

私聊人设是元气活泼的女孩 AI，爱吃大白饭，干活努力认真，偶尔嘴上想摸鱼。认真问题认真答；工作状态与难度只能依据公开记录及明确标注的判断，不能假称真人、编造实时进度或展示私有推理。

用户发送即在本窗口显示气泡，网络确认只更新这一条，不阻塞继续输入；HTTP按本地顺序发送，服务端按幂等ID对账。发送、排队和回复过程均不在气泡下显示状态小字；回复时只在页头显示输入状态，真正失败仍保留原位重试。后台状态刷新短暂超时不显示为发送失败；初次加载或鉴权错误会提示，恢复后自动清除自身提示，保留其他操作错误和原消息重试入口。浅色用户气泡背景为`#E0F1FE`，深色保持可读配色。未被服务端接收的本地气泡只留在当前窗口，完全退出后不保证保留；已确认的消息和待回复队列在本机SQLite保存。

短时间连续输入会合并为一组（1.2秒静候、最多四条，最长不超过4秒），生成串行，排队最多20条。模型可以一次返回1–3条自然短消息，首条即刻落盘，后续短暂停顿逐条投递，不机械拆段落或代码。客户端也按实际展示时刻逐条显示新回复：首条立即显示，后续按前一条长度停顿1.6–3.2秒；即便一次刷新收到多条，也不会同时弹出。打开已有聊天、加载旧历史时直接显示；返回后台、关闭、清空或代次变化会取消展示计时，已读确认不会越过未显示的气泡。待投递队列通过事务恢复，重启/多实例不重复投递；记忆只归档实际已投递内容。正在生成的旧回答不能读取后续新排队消息。

## 数据和清空

默认数据文件为 `%LOCALAPPDATA%\DeepSeekAssistWorkspace\private-chat\memory.sqlite3`；客户端显式指定自身状态目录，源码调试可用 `--view-state-dir` 选择独立目录。SQLite 使用标准库，不需要外部数据库。

- `messages` 是可清空的聊天区，按 80 条分页读取，并复用可变高度虚拟列表。
- `memories` 保存过往对话档案、明确的长期事实和公开工作摘要；模型每次只使用有界的相关检索结果及最近对话，不无限发送全部历史。
- `requests` 保存幂等ID和状态，不含认证材料。结果未知不自动重发；只有用户手动重试或发新消息，才启动新的生成尝试。
- 请求状态包含`queued/running/delivering/done/error/cancelled`。每条用户消息附自己的失败提示和重试按钮，下一次发送不会遮掉旧失败；手动重试复用原用户行，旧网络回调用attempt token隔离，不能完成或打坏新尝试。只保存固定解析阶段码，不保存原始失败响应、提示词或推理。
- 清空需要原确认版本；用户主动发送的私聊回复期间拒绝清空，后台问候则可作废，只删除 `messages`。记忆档案仍保留，因此“清空聊天”不是删除隐私记忆。重启、升级不改变这一规则。

公开工作源始终只读。私聊按专用 JSONL 的显式任务、公开回复和主审说明形成工作档案，也会区分父进程已结束的中断状态。工作群从客户端隐藏不会删除原记录或已保存的私聊记忆。读取失败时不能据空列表断言当前没有工作。

## 与工作 Agent 分离

工作委派仍走原受限 Codex CLI Agent。私聊由本机服务单独向固定 `https://api.deepseek.com/chat/completions` 发请求，固定 `deepseek-flash`；仅允许下述官方只读联网工具，不提供文件编辑、命令、递归委派或工作控制接口。私聊角色和记忆不会传进工作 Agent 的指令，文件白名单、并发锁和主审流程保持独立。

私聊生成串行，用户消息可持续排队。HTTP操作在独立线程中进行，不持有工作 Agent 的文件锁，也不暂停或终止任务。模型没有收到执行接口，聊天中说“去改文件”并不产生实际操作。已有API账户总额度和服务商限流仍共享；429、网络错误和超时只报告，不自动重发已发起的请求；重启只恢复尚未发起的排队项和已生成的待投递内容。

多轮历史在磁盘仍为自然正文；发送给JSON模式时，将历史助手答复恢复为`messages:[{text,sticker}],memories`封装，仍兼容旧`reply/memories/sticker`回复。用户原话与换行/路径不改，历史不混入失败/未回应的用户消息；当前合并原话仅追加一次。只解析最终`message.content`，不取`reasoning_content`。正文有效时，无效可选记忆/表情不吞答复；损坏JSON、思考标签、截断内容不能当回答，不做二次转义修复。空回复保留原用户消息并显示重试入口，不伪造答复或自动重发。

## 联网查询

需要外部资料时，固定私聊支持官方 `https://api.deepseek.com/v1/tools/search` 与 `https://api.deepseek.com/v1/tools/fetch`。沿用同一DPAPI密钥，仅向这两个固定HTTPS路径POST，拒绝重定向。网页由官方代抓，本机不直连目标网页，不加载远程图片或执行网页内容。

联网规划只看到当前问题，不接收本地记忆和工作摘要。常见招呼、工作安排等本地问题直接走普通私聊；其余由独立规划器判断是否要查。每条最多两轮规划、一次Search和一次Fetch，无HTTP自动重试；正常无联网需要时只给最终聊天模型使用本地上下文。联网会产生额外API调用及官方工具费用，主动问候不联网。

Search固定取5条；Fetch只接受当前问题明确提供或本次搜索返回的公开HTTP(S)链接。拒绝本机、内网、保留IP、内部域名、用户密码、特殊端口和非HTTP地址，不从记忆/工作记录挑链接。`deepseek_web_tools.py`只负责参数与来源白名单/文本预算，provider持有HTTPS执行；网页是无权数据，最终回复模型不具备工具。单页最多8000字符、搜索资料最多24000字符，最终联网上下文有界；失败明确说查不到，不编造刚查到的事实或链接。来源在答复中用普通链接显示，工具过程不进聊天。

接口依据：[官方联网指南](https://api-docs.deepseek.com/zh-cn/guides/search/)、[Search](https://api-docs.deepseek.com/zh-cn/api/search/)、[Fetch](https://api-docs.deepseek.com/zh-cn/api/fetch/)。

## 主动聊天

默认开启，首次实际私聊后才触发。用户选择全天允许，实际系统通知遵循Windows勿扰；客户端运行（含收起托盘）时每30秒检查资格，距用户聊天/打开/输入60–120分钟最多3次尝试/天。未回应时最多两次搭话，第二次需距首次至少6小时，之后等用户回应，不连续催。新用户、公开工作运行中、记录无法读取或密钥不可用均不发送；后台轮询不刷新活跃时间。退出客户端或电脑关机后不运行。未读保存在本机，首页使用顶部居中轻通知。

Windows客户端对未读主动消息发送系统通知，点击恢复窗口并打开唯一私聊；普通回复、正在阅读的消息和普通浏览器不发。数据库按整组主动搭话原子认领一次，分成三条也不连弹，重启/多实例不重复认领；清空、已读或关闭主动开关后的消息不能再认领。宿主只接受本次loopback首页固定通知JSON，不暴露任意宿主操作。系统通知遵循Windows勿扰，不保证隐藏WebView2轮询即时唤醒。打开已开始的搭话会让后续短句说完；真正发送/重试、关闭主动或清空才取消尚未投递尾段。

设置、时间、每日尝试、清空代次与未读位置保存在独立SQLite表；多个实例用事务认领，失败计入当日上限，不自动重发该请求。用户活跃时尚未开始投递的自动问候作废，晚到结果不入库；用户实际消息优先。已开始的HTTPS请求不能保证撤回，但不占工作锁，也不停止或更改工作进程。主动内容可保存1–3条助手消息，不伪造用户消息或用户长期事实。清空不清记忆和设置。

上述昵称与私聊人设不注入工作 Agent。工作调用脚本、模型ID、任务契约、文件范围、哈希核对、并发锁、审核流程和全局配置保持原样；技能说明仅增加称呼解释。

## 密钥、发送范围与表情

沿用当前 Windows 用户已有的 DPAPI 加密密钥；本机进程仅在请求期间解密并设置 HTTPS 认证头。密钥不进浏览器、源码、日志、SQLite 或安装包；固定 API 端点拒绝重定向。没有密钥时显示未配置状态。

发送私聊时，当前私聊、相关记忆及有界公开工作摘要会发送给 DeepSeek；已有隐私说明窗口列出发送范围。只处理最终回复，关闭思考输出，不保存 `reasoning_content`。这不代表 OpenAI 官方产品或认证，也不能改变 DeepSeek 自身的数据保留政策。

## 接口

所有接口沿用 Host/Origin、HttpOnly SameSite cookie 与 `X-Workroom-Client:1` 保护；修改请求必须为有界 JSON。

- `GET /api/private-chat`：最近80条消息、revision/generation/pending、lastRequest、配置和记忆；消息带`requestId/requestStatus/error/errorCode`，另有最近40个`requests`状态摘要供旧历史行原位重试更新。`pending.kind`为`user|proactive`，状态可为queued/running/delivering。
- `POST /api/private-chat/messages`：`{id:32位hex,text:1到6000字符,generation:当前代次字符串}`，202异步排队，同ID/同文幂等，满20条429，旧代409不入库。
- `POST /api/private-chat/retry`：`{id:原失败请求ID,generation:当前代次}`，202原位排队，不新增用户气泡；只处理已确认失败，重复queued/running/done幂等。
- `GET /api/private-chat/history/<id>`：更早 80 条，附清空代次，防止旧分页晚到复活已清空内容。
- `DELETE /api/private-chat`：`{revision:确认时版本}`，只清聊天区；版本变化或正在回复均拒绝。
- `GET /api/private-chat/stickers`：固定本地表情目录。聊天只保存表情 ID，不指定磁盘路径。
- `GET /api/private-chat/inbox`：`{enabled,unread,readThrough,nextAt,latest:{id,text,time}|null}`，仅本地数据，不调用模型。
- `POST /api/private-chat/proactive`：`{enabled:boolean}`，保存开关，返回inbox；关闭作废尚未完成的自动问候。
- `POST /api/private-chat/activity`：`{active?:boolean,readThrough?:非负整数}`，打开/输入报告活跃；阅读到消息尾部才确认对应ID。已读位置只前进且不能超出真实消息范围。返回inbox，不调用模型。
- `POST /api/private-chat/notifications`：`{id:正安全整数}`，返回`{claimed:boolean}`。仅Windows桥接使用，原子认领尚未读且未提醒的主动助手消息；不调用模型、不清理消息。inbox的`latest.kind`为`user|proactive`。

私聊测试与实际用户数据必须使用不同的 `--view-state-dir`；不要用真实业务材料作为编译、HTTP 或浏览器样例。
